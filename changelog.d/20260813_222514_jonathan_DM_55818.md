### Bug fixes

- Stopped serving the SSRF guard's resolution result for a redirect hop Ook refused. The guard's reason names the hop's host and the address it resolves to *from inside the cluster*, and for a redirect-hop rejection that reason was not a transient message to one client: it was stored on the negative-cache row and replayed in the 502 body to every client for the whole negative-TTL window, so an origin that redirected an inventory to an internal cluster name published Ook's own DNS view. A rejected hop now yields a generic `Upstream redirected the inventory to a disallowed target` detail, and the specific reason is logged instead — in one warning record naming both the URL the client requested and the hop that was refused, since the served detail and the negative-cache row now name only the former and the guard's own rejection log names only the latter. The `400` path for a *client-supplied* URL is unchanged: that host is the client's own choice and the reason tells them what to fix.
