### Bug fixes

- Closed two ways an upstream `Location` header could escape Ook's hand-rolled redirect loops. httpx joins a 3xx `Location` itself even under `follow_redirects=False`, so a target that only overflows its 65,535-character URL limit once joined raises `httpx.InvalidURL` from inside the request — before any response is returned, which is why the intersphinx cache's own join could never catch it. `httpx.InvalidURL` is not an `httpx.HTTPError`, so it escaped both intersphinx fetch paths: on the request path as an unhandled 500 that negatively cached nothing and re-walked the chain on every repeat, and on the refresh path as an abort of the whole batch at the row that then sorted stalest-first on every subsequent run. It is now converted in the hop loop into the same malformed-redirect failure the service's own join raises, so it is a negatively cached 502 on the request path and a single skipped inventory on the refresh path. The link checker already caught this at its own error boundary.

- Stopped following a target no origin ever named when a redirect response repeats its `Location` header. Reading the header concatenated the values with `", "`, which the join then percent-encoded into a single URL naming neither target — one that keeps the origin's host often enough to pass the SSRF guard, be fetched, and 404. In the intersphinx cache that negatively cached a working inventory and 502'd every Documenteer build for the negative-TTL window; in the link checker it reported a working link as broken. Both hop loops now follow the first `Location` value.
