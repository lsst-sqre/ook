### Bug fixes

- Hardened the intersphinx cache's redirect loop against failures that are not `httpx` errors, which previously escaped both fetch paths' handlers. A redirect hop whose host will not resolve — a retired hostname, a transient DNS failure, or a label IDNA cannot encode — is now reported by the SSRF guard as a rejection, so it becomes a negatively cached 502 on the request path instead of an unhandled 500 that re-walked the origin chain on every request, and skips only its own inventory on the refresh path instead of aborting the batch at the row that then sorts stalest-first on every subsequent run. A `Location` that cannot be resolved to a URL is likewise converted into the same upstream-failure taxonomy. The hop cap is now enforced on the hop count alone, before the target that exceeds it is joined, guarded, or resolved, so an over-long chain always reports `Exceeded 20 redirects` rather than whatever the 21st target — a URL the fetch was never going to request — happened to fail on. A guard rejection of the URL the client actually asked for, including one whose host does not resolve, is still a 400.
