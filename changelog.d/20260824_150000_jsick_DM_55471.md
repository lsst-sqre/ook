
### New features

- `POST /ook/linkcheck/checks/{id}/contributions` now also accepts results for a member URL Ook recorded `broken` without ever receiving a response — a connection, TLS, or DNS failure at Ook's own egress, which shows as `broken` with a null `status_code`. That verdict rests on evidence Ook never obtained, which is the same "could not verify from its own vantage point" case bot-blocked URLs are eligible for, so a client that did reach the origin can settle it: a contributed 2xx resolves the URL to `ok` (or `redirected`) with its failing streak cleared and the contributing repository recorded, and a contributed failure simply extends the streak. A `broken` URL that did answer with a status code remains ineligible, because that verdict is Ook's own evidence; so do `pending`, `ok`, `redirected`, `failing`, and `unsupported`. The rejection reason stays `not_blocked` for wire compatibility, and its `message` now names the URL's actual status and the status code behind it, if any.
