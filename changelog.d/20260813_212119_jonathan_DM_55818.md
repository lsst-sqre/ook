### Bug fixes

- Bounded an intersphinx origin fetch as a whole, not just hop by hop. The 30-second request timeout now serves as a single time budget for the entire fetch: it is taken when the fetch starts and covers every redirect hop's request, every hop target's SSRF-guard host resolution, and the terminal response's body read alike, with each hop's request additionally given no more than the time left and refused outright once the budget is spent. Previously an origin that answered each redirect just inside the per-request timeout could stretch one cold-miss fetch to the 20-hop cap times that timeout, plus a DNS resolution per hop with no timeout at all — all of it holding the request's database session open long after the client had given up, so a few such URLs could exhaust the connection pool. An exhausted budget is reported like any other upstream failure: a negatively cached 502 on the request path, and a single skipped inventory on the refresh path.
