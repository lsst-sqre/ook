### New features

- Link-check results now record where they were observed from. The per-URL entries of a check's poll response and the URL read endpoint (`GET /ook/linkcheck/urls`) carry `result_source` (`server` or `contribution`) and `contributed_by`, so a report can render "externally verified by <repository> CI" for a URL that Ook's own egress is bot-blocked from. Ook's own checks report `server` with no repository, and a later server check takes a contributed URL's state back over. This is the reporting half of the forthcoming link-check contributions endpoint.

### Other changes

- Added the `linkcheck_contribution` table, which records each contributed per-URL result alongside the GitHub Actions provenance (repository, run, workflow ref) it arrived with. Contribution rows are retained with their check and purged with it. This requires Alembic migration `6f68334c9c9b` to `0bfe17a5f990`, which also adds the `result_source` and `contributed_by` columns to `checked_url`; existing results backfill to the `server` source.
