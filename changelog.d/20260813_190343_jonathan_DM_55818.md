### New features

- `GET /ook/intersphinx/inventory` now reports a permanently-moved inventory URL with an `X-Ook-Inventory-Permanent-Redirect` header naming the URL the origin's redirect chain resolved to. It is emitted on a `304` as well as a `200`, so a client that holds the current bytes and only ever revalidates still learns that the URL in its configuration is stale. The header appears only when *every* hop of the chain was permanent (a 301 or 308), which is the case where the requested URL should be updated at its source; a chain with any temporary hop gets no header, since a `latest` alias legitimately moves and there is nothing for a doc author to fix. The value is read from the columns recorded at fetch time, so a cache hit reports it without re-contacting the origin.
