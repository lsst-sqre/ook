### New features

- `GET /ook/intersphinx/inventory` now says how it obtained the copy it is describing, with an `X-Ook-Inventory-Cache-Status` header valued `hit` (served from a cached copy fetched within the freshness TTL), `stale` (served from a cached copy fetched longer ago than that TTL — still a cache serve rather than an error, since a copy past its TTL is deliberately retained for availability while the background refresh job revalidates it, so it is read alongside `Age`), or `miss` (not cached when the request arrived, so the origin was fetched synchronously to answer it). Nothing else on the response distinguishes the three: a cold miss stamps the same just-now fetch time a fast hit reports, and telling either of those from a stale serve needs the freshness TTL, which the client does not hold. The header rides the `304` as well as the `200`, where it describes how Ook obtained the copy it compared the client's validator against — so a cold miss whose freshly-fetched bytes turn out to match an `If-None-Match` reports `miss`, not `hit`. The three values are the vocabulary the cache already logged as `cache_status`, now a shared enum that both the header and those log fields read from, so the two cannot drift apart.
