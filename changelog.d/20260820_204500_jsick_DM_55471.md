### New features

- Added `POST /ook/linkcheck/checks/{id}/contributions`, which lets a client that re-checked a link from its own vantage point contribute what it saw. Only URLs that are members of the check and currently `blocked` are eligible — the case Ook's own egress cannot resolve — and a batch applies entry by entry, so ineligible entries come back in `rejected` with a per-URL reason (`not_a_member`, `not_blocked`, `unsupported_url`, `duplicate`) while the rest still apply. Accepted results run through the same status-transition engine, retry ladder, and `OOK_LINKCHECK_FRESHNESS_TTL` as Ook's own checks: a contributed success resolves the URL to `ok` (or `redirected`, with its redirect metadata), a contributed 404 advances the failing-to-broken ladder, and a contributed 403, 429, or 503 is inconclusive and leaves the URL `blocked`. Each request must carry a GitHub Actions OIDC id-token minted for the deployment's audience; its `repository`, `run_id`, and `workflow_ref` claims are recorded as the contribution's provenance, and the request's `environment` block is advisory. Like the check submission endpoint, it is write-protected by Gafaelfawr at the ingress.
