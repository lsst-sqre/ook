### New features

- `GET /ook/authors` now refuses the parameter combinations its `orcid` lookup cannot answer. Sending `orcid` together with `search` is a `422` rather than a silently-run fuzzy name search: the two modes return different models under different match semantics, so letting one win would hide a client bug behind a plausible body. Sending `orcid` together with `cursor` is likewise a `422` — `author.orcid` is unique, so an ORCID matches at most one row and there are no pages to walk. For the same reason the ORCID response carries neither a `Link` nor an `X-Total-Count` header. Both rejections are located at the `orcid` parameter, matching the `422` a malformed ORCID already produces, so every bad request to that parameter lands on one error surface. `limit` always carries a default and so cannot be told apart from an absent one; it is accepted on the ORCID path and has no effect. The endpoint's OpenAPI description now spells all of this out alongside the accepted ORCID spellings.
