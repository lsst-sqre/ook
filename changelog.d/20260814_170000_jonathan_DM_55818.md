### Bug fixes

- Scrubbed the SSRF guard's rejection reason from a failed intersphinx refresh. The refresh job re-guards a cached inventory's stored URL before fetching it — the check that catches a once-public host DNS has rebound to a private address — but its rejection reason names that host and the address it resolves to *from inside the cluster*, and the reason was written straight to the row's stored error, which the cache replays verbatim in the 502 body of every later request that finds the row a live negative-cache entry. A rejected refresh now stores a generic detail and logs the specific reason as a structured warning, matching how a redirect hop the guard refuses is already handled. A guard rejection of a *client-supplied* URL — one no parser accepts, one that is not `https`, or one pointing at a non-public address — still answers 400 with the specific, actionable reason: that detail names a host the client itself chose and is never stored.
