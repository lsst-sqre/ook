### Backwards-incompatible changes

- Renamed every datetime-valued field in the link-check API so that it carries the `date_` prefix the rest of Ook's API already uses: `checked_at` is now `date_checked`, `last_checked_at` is `date_last_checked`, `last_ok_at` is `date_last_ok`, `failing_since` is `date_failing_since`, and `next_check_at` is `date_next_check`. This changes the check-status response (`GET /ook/linkcheck/checks/{id}`), the URL and origin-link read endpoints, and the `results[].checked_at` field of the new contributions request body. Clients that read or send those fields must be updated; Documenteer's link-check client is the only known consumer, and the release carrying it is still unpublished. The underlying `checked_url` and `linkcheck_contribution` columns are renamed in place by a migration, so stored history is preserved.
