### New features

- New `/ook/intersphinx/sources` registry API naming the documentation sites Ook pulls Sphinx `objects.inv` inventories from. A registration is an inventory URL plus a human title (which surfaces as the `collection_title` of every link ingested from the site) and an `enabled` flag; `POST`, `GET` (single and list), `PATCH`, and `DELETE` are all supported, and `GET /ook/intersphinx/sources?enabled_only=true` narrows the listing to the sites the next ingest run will visit. The inventory URL is a registration's identity, so registering one that is already registered — or moving a registration onto another's URL — is a `409` rather than a second row, and an `http` URL is refused up front because the ingest path can only fetch over `https`. Each registration also reports when Ook last attempted to ingest it (`date_ingested`), how that attempt ended (`last_status`), and why it failed (`last_error`); those three are written by ingest runs and refused in a request body, so a registration cannot claim an outcome it never had. Writes are gated by the `exec:admin` scope at the Gafaelfawr ingress — not the `write:intersphinx` scope that warms the inventory cache — since registering a site commits Ook to serving links from it.
- New intersphinx ingest pipeline that turns those registrations into documentation links. `ook ingest-intersphinx` — intended to run as a scheduled cron job — pulls every enabled source's `objects.inv` through the intersphinx inventory cache, parses it, derives each Python object's place in the dotted-name hierarchy, and replaces that site's links in one transaction per site; entities no source documents any more, neither directly nor anywhere below them in the hierarchy, are pruned. Re-running is idempotent. A site whose inventory cannot be fetched or parsed keeps the links from its last successful ingest, has the failure recorded as `last_status` and `last_error` on its registration, and does not stop the run — the command then exits nonzero once the run has finished, so the CronJob shows red for a site Ook has stopped refreshing. `POST /ook/ingest/intersphinx` triggers the same run on demand and reports each visited source's outcome in its body; giving it a `source_url` ingests that one registered source, whatever its `enabled` flag says, which is how a registration is tried out before being turned on. Like the registry, it requires the `exec:admin` scope at the ingress.
