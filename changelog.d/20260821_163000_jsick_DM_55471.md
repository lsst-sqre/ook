### Other changes

- Documented Ook's `date_` prefix convention for datetime-valued API fields in the development guide's style guide, covering both JSON field names (`date_created`, `date_checked`, `date_next_check`) and the capitalized header form Ook's own response headers use (`X-Ook-Inventory-Date-Fetched`), along with its one exception: a field carrying a verbatim HTTP header value, such as the intersphinx domain's `last_modified`, mirrors the wire name instead. A new introspection test enforces the field-name half of the convention against every Pydantic model under `src/ook/handlers`, resolving `Annotated[...]` wrappers and optional unions, and fails naming the offending model and field. It needs no database or application fixture, so it runs in the containers-free `test-unit` session.
