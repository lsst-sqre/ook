### Other changes

- Made a redirecting intersphinx inventory fetch cheaper per hop. Each hop's response body is now read and discarded under a fixed 8 KB cap instead of being left unread, so the HTTP/1.1 connection goes back in the pool rather than being closed: the motivating `www` → `docs` → `docs` chain opened three TCP+TLS connections to the same host on every cold miss and every refresh, and now reuses one. A hop answering with more than the drain cap is still abandoned, and hop bodies remain uncounted against `max_content_size`, which governs the terminal inventory response alone. The SSRF guard also no longer re-resolves a host it already accepted earlier in the same chain — the cluster has no caching resolver and `ndots` search expansion multiplies every external-name lookup — while still resolving each new host, still checking the https-only invariant on every hop, and forgetting the chain's validated hosts when the fetch ends.
