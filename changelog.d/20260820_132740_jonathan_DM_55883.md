### Other changes

- Sped up the test suite roughly five-fold on CI. The test fixtures now start the application lifespan (including the Kafka consumer) once per pytest session instead of once per test, and reset the database between tests with a bounded, lock-diagnosing `TRUNCATE` instead of recreating the schema. The suite runs under pytest-xdist with one worker per usable CPU by default (capped at eight, since the workers share the single Docker VM that serves the PostgreSQL and Kafka containers), with per-worker PostgreSQL databases and Kafka topic/consumer-group namespaces; pass `-n 0` to pytest for a serial run, and debugging invocations (`--pdb`, `--trace`, `-s`, `--capture=no`) drop to a single process on their own. Schema and migration tests now run against a dedicated database so DDL never contends with the shared application's connection pool. Because the shared broker keeps consuming between tests, the `app` and `factory` fixtures now drain the Kafka work a test published before its HTTP mocks come down, and the test environment turns off the link checker's per-host politeness delay so that drain never waits on it.
- Restructured CI to run type checking and a new containers-free `test-unit` nox session as parallel jobs alongside the test job, and enabled uv dependency caching in all jobs. The `test-unit` session gives sub-second local feedback on tests that need no database or Kafka; its positional arguments narrow that run (options tune it, a path under `tests/` selects within it) while the infrastructure ignore list always applies. A test file that the ignore list misses now fails at setup naming that list, instead of dying in a connection retry loop against the session's placeholder servers with nothing to point at.
