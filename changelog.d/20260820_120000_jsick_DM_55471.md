### New features

- Added a GitHub Actions OIDC verifier service. It fetches and caches GitHub's JWKS, verifies a presented id-token's signature, issuer, audience, and expiry, and returns the `repository`, `run_id`, and `workflow_ref` claims as provenance. A token whose key ID is not in the cached key set triggers an off-schedule refetch, so a GitHub key rotation mid-TTL does not reject good tokens; that refetch fires at most once a minute, so tokens naming invented key IDs cannot amplify into one request to GitHub apiece, and a failed refetch keeps verifying against the cached keys. The verifier is a process-wide singleton on the shared HTTP client so its key cache applies across requests. This is the provenance attestation the forthcoming link-check contributions endpoint requires — a valid token from any repository is accepted, because authorization remains the Gafaelfawr scope at the ingress.

### Other changes

- Added the required `OOK_OIDC_AUDIENCE` configuration setting, the audience GitHub Actions OIDC id-tokens must be minted for. Set it to the deployment's public base URL so a token minted for one Ook environment is not replayable against another. Every Phalanx environment must set this setting for Ook to start.
