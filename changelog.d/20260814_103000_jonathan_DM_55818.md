### Bug fixes

- Enforced the intersphinx inventory fetch's whole-fetch time budget by cancellation, and brought the requested URL's SSRF guard inside it. The budget was previously only *checked* between redirect hops and between body chunks, and otherwise handed down as per-call httpx timeouts — but httpcore re-arms the read timeout on every socket read, so an origin trickling response-header bytes kept a single hop alive far past the budget (and a hop's connect, write, and header-read phases each got the full remainder in turn). On the cold-miss path that hop holds the request's DB session open for the duration, which is the session-exhaustion hazard the budget exists to close. The guard on the requested (or stored) URL was worse off still: it ran before the budget existed, so a hung resolver ladder — likely in a cluster with no caching resolver and `ndots` search expansion — blocked the request or stalled the serial refresh batch outside every bound the fetch had. Both are now wrapped in a single `asyncio.timeout` covering the guard and the whole redirect chain, whose expiry maps to the existing spent-budget error: a negatively cached 502 on the request path, a per-inventory skip on the refresh path. Per-call httpx timeouts remain as belt and braces, and the recorded outcome of an exhausted budget is written outside the cancelled region so the failure is never lost.
